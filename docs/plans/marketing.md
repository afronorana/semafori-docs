# Marketing Plan

This document defines how to position, launch, and grow the AI Agent Status Light.

The product is a physical desk gadget for developers using AI coding agents. The strongest marketing angle is not "a traffic light." It is "a physical status indicator for your AI coding agent."

## Positioning

### Core Position

```text
AI Agent Status Light is a physical desk light that shows what your AI coding agent is doing.
```

### Short Version

```text
A traffic light for Codex and AI coding agents.
```

### Practical Value

- Know when the agent is idle.
- Know when the agent is thinking.
- Know when the agent is busy running tools.
- Know when something failed.
- Make invisible AI work visible on your desk.
- Give AI coding sessions a physical presence.

### Emotional Value

- Feels like a real desk gadget.
- Makes AI work visible and satisfying.
- Creates a "developer cockpit" feeling.
- Looks good in desk setup photos and videos.

## Target Customers

### Primary ICP

AI coding power users:

- Codex users.
- Claude Code users.
- Cursor users.
- Developers using terminal-based agents.
- Solo builders.
- Indie hackers.
- Engineers who run long agent tasks.

Why they buy:

- They already understand the problem.
- They like developer tools.
- They buy desk gadgets.
- They share setups publicly.
- They can tolerate early software limitations.

### Secondary ICP

Developer teams:

- Small engineering teams.
- Agencies.
- AI-native startups.
- Internal tools teams.
- DevRel teams.

Why they buy:

- Fun team desk accessory.
- Shared visible status during pair/agent work.
- Good onboarding gift for AI engineering teams.

### Later ICP

Broader productivity users:

- Makers.
- Streamers.
- Home office users.
- Desk setup enthusiasts.

Do not start here. They need more explanation and care less about Codex hooks.

## Messaging

### Main Landing Page Headline Options

- A traffic light for your AI coding agent.
- See what Codex is doing without checking the terminal.
- Make your AI agent visible on your desk.
- A physical status light for AI coding work.

### Subheadline

```text
AI Agent Status Light connects your desktop AI coding tools to a small ESP32-powered traffic light, showing idle, thinking, busy, and error states in real time.
```

### Feature Bullets

- Green: idle.
- Yellow: waiting or thinking.
- Red: busy or error.
- Local desktop bridge.
- Works over your Wi-Fi.
- Manual IP and auto-discovery.
- Codex integration.
- Open local HTTP API.

### Proof Points To Build

- Real desk demo video.
- Codex prompt -> yellow.
- Tool execution -> red.
- Finished -> green.
- Setup hotspot flow.
- Desktop app screenshot.
- Open API docs.
- Beta user desk photos.
- Short customer quotes.

## Brand Rules

Do:

- Use developer language.
- Show real device photos/videos.
- Show the desktop app.
- Show the LEDs changing from actual Codex activity.
- Say "desk accessory", "developer gadget", "AI agent status light".

Avoid:

- Calling it a toy.
- Child-oriented visuals.
- Overpromising support for every AI tool.
- Making it look like a safety device.
- Using fake renders after real prototypes exist.

## Launch Strategy

Use a sequence of small launches instead of one giant reveal.

### Launch 1: Build In Public Prototype

Goal:

- Validate attention.
- Recruit beta users.
- Learn messaging.

Assets:

- 10-second video of Codex changing the light.
- Photo of the physical device on a desk.
- Screenshot of the desktop app.
- Short explanation of the local bridge.

Post ideas:

- "I built a tiny traffic light that shows what Codex is doing."
- "Yellow means my AI agent is thinking. Red means it is running tools. Green means idle."
- "The unnecessary desk gadget I now actually use every day."

Call to action:

- Join waitlist.
- Apply for beta.

### Launch 2: Closed Beta

Goal:

- Get 20-50 real users.
- Find setup issues.
- Collect testimonials and photos.

Founder actions:

- Manually onboard every beta user.
- Watch at least 5 users install it live.
- Ask what confused them.
- Ask what they expected the lights to mean.
- Ask if they kept it plugged in after 7 days.

### Launch 3: Paid Pilot

Goal:

- Prove willingness to pay.
- Test price.
- Test support load.

Offer:

- Limited first batch.
- Numbered or batch-labeled units.
- Clear shipping window.
- Clear compatibility: Codex first.

### Launch 4: Public Launch

Channels:

- Product Hunt.
- Hacker News Show HN.
- X/Twitter.
- LinkedIn.
- Reddit, carefully and only in relevant communities.
- Indie Hackers.
- Dev.to or personal blog.
- YouTube Shorts / TikTok / Instagram Reels for desk demo.

Primary CTA:

- Buy now if inventory exists.
- Preorder if manufacturing date is known.
- Join waitlist if not ready to ship.

### Launch 5: Post-Launch Content

Content:

- How it works technically.
- ESP32 firmware walkthrough.
- Electron bridge architecture.
- Codex hook integration.
- Manufacturing journey.
- Desk setup posts.
- Customer photos.
- New integrations.

## Proven Early-Stage Method

Follow this principle:

```text
Do things manually until the repeatable pattern is obvious.
```

For this product, that means:

- Personally recruit the first users.
- Personally onboard them.
- Personally debug Wi-Fi setup problems.
- Personally inspect returned units.
- Personally ask for photos and feedback.
- Personally write the first support docs from repeated questions.

Do not jump to paid ads before:

- Setup works.
- Returns are low.
- Users understand the value.
- A clear message converts organically.

## Channel Plan

### X / Twitter

Use for:

- Short videos.
- Build updates.
- Founder story.
- Demos.

Cadence:

- 3-5 posts per week while building.
- Daily during launch week.

What works:

- Real videos.
- Specific technical details.
- Visible progress.
- Asking for feedback.

### LinkedIn

Use for:

- AI workflow angle.
- Team productivity angle.
- Founder/building hardware story.

Cadence:

- 1-2 posts per week.

What works:

- Clear problem framing.
- Demo video.
- Practical explanation.

### Hacker News

Use for:

- Technical launch.
- "Show HN" post when there is a real working demo.

What must be ready:

- Technical write-up.
- Demo video.
- Clear architecture.
- Honest limitations.
- Open API docs.

Avoid:

- Pure sales copy.
- Fake urgency.
- Hiding that it is a paid product.

### Product Hunt

Use for:

- Public launch when landing page, assets, screenshots, and onboarding are polished.

Prepare:

- Maker profile.
- Product tagline.
- Gallery images.
- 30-60 second demo video.
- First comment from maker.
- Launch-day reply schedule.
- Email list announcement.

Product Hunt itself says the best launch day is the day you are most prepared. For planned launches, use the daily reset timing and be ready to respond all day.

### Reddit

Use carefully.

Candidate communities:

- AI coding communities.
- ESP32 communities.
- Developer productivity communities.
- Desk setup communities.

Rules:

- Read each community's self-promotion rules.
- Share a real build story, not just a buy link.
- Ask for feedback.
- Be transparent that you made it.
- Do not copy-paste the same post everywhere.

## Kickstarter / Crowdfunding Marketing

Crowdfunding is a marketing and financing tool, not a substitute for manufacturing validation.

Use it only when:

- There is a working prototype.
- Manufacturing path is credible.
- Costs are modeled.
- Timeline includes contingency.
- Product photos/videos are real.
- Backers can understand risks.

Campaign story:

- AI coding agents are becoming part of daily work.
- Their status is trapped inside terminals and desktop apps.
- This product makes agent activity physical and glanceable.
- It is local, simple, and developer-friendly.

Rewards:

- One unit.
- Two-pack.
- Team five-pack.
- Early beta batch.
- Optional founder edition if it does not complicate manufacturing.

Avoid too many reward tiers. Every tier adds fulfillment risk.

## Paid Ads

Do not start with paid ads.

Try paid ads only after:

- Organic messaging converts.
- Product page converts.
- Support burden is known.
- Gross margin supports CAC.
- Returns are low.

Possible ad tests later:

- Retargeting site visitors.
- X ads targeting AI developer tools.
- Reddit ads in relevant tech communities.
- YouTube remarketing for demo viewers.

Small hardware ads can burn cash quickly. Organic technical storytelling is the better first channel.

## Proven Methods To Follow

- Launch early with a working prototype.
- Talk to users constantly.
- Manually recruit the first 10-100 users.
- Keep the first market narrow: Codex/AI coding users.
- Use real demos over polished claims.
- Use small repeated launches instead of one giant launch.
- Build trust through transparent manufacturing updates.
- Keep technical docs public enough for developers to trust the product.
- Collect customer photos and quotes.
- Add integrations based on actual demand, not guesses.

## Common Mistakes To Avoid

- Marketing as a novelty toy.
- Launching before setup is reliable.
- Spending on ads before organic conversion works.
- Hiding manufacturing risk during preorders.
- Claiming broad compatibility before integrations exist.
- Making the landing page too abstract.
- Using only renders when real prototypes exist.
- Ignoring support and onboarding as part of marketing.
- Overbuilding brand before validating the core message.
